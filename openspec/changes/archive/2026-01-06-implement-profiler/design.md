# 设计文档：Profiler 模块架构

## 架构概述
`Profiler` 模块旨在对特定市场的持仓者进行深度分析。它由三个核心组件组成：数据采集器、链上分析器和打分引擎。

## 核心组件

### 1. GammaClient (数据采集)
- **职责**：调用 Gamma API (`/positions?market_active_id=...`) 获取持仓排名。
- **输入**：Market ID (Gamma 内部 ID)。
- **输出**：持仓者地址列表及其持仓量。

### 2. ChainAnalyzer (链上分析)
- **职责**：通过 `ethers.js` 与 Polygon 网络交互。
- **核心逻辑**：
    - **首笔交易查询**：通过二分法或扫描早期区块查找钱包的最早活动记录。
    - **余额查询**：查询当前 USDC 余额。
    - **入金来源分析**：识别是否从交易所（如 Binance, OKX）或跨链桥入金。

### 3. Scorer (打分引擎)
- **打分维度**：
    - **账号新鲜度 (Max 40分)**：
        - < 24h: 40分
        - < 72h: 30分
        - < 1周: 10分
    - **资金实力 (Max 30分)**：
        - > 50k USDC: 30分
        - > 10k USDC: 20分
    - **专注度 (Max 20分)**：
        - 仅参与当前 1 个市场: 20分
        - 参与 < 3 个市场: 10分
    - **历史表现 (Max 10分)**：
        - 历史胜率 > 80%: 10分

## 集成流程
1. `Sentinel` 检测到异动。
2. `Sentinel` 调用 `Profiler.analyze(marketId)`。
3. `Profiler` 异步启动分析任务：
    - 获取 Top 20 持仓者。
    - 并发查询这些钱包的链上数据（带限流）。
    - 计算得分。
4. `Profiler` 返回得分超过阈值（如 60分）的钱包列表。
5. `Messenger` 格式化并推送。

## 性能优化
- **缓存**：对已分析过的钱包地址进行缓存（有效期 24h），避免重复查询 RPC。
- **并发控制**：使用 `p-limit` 或类似机制限制 RPC 请求的并发数。
