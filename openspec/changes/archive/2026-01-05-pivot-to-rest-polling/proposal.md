# 提案：转向 REST API 轮询架构

## 摘要
将 Poly-Sniper 的数据获取方式从不稳定的 WebSocket 订阅转向基于 REST API 的高频轮询（10秒/次）。此举旨在提高系统在代理环境下的稳定性，简化架构，并满足 1000+ 市场规模的监控需求。

## 动机
1. **稳定性问题**：WebSocket 在代理环境下容易断线且重连逻辑复杂。
2. **API 限制**：WebSocket 对单个连接的订阅数量有限制（通常 200-500），监控 1000+ 市场需要管理多个连接。
3. **需求匹配**：用户明确表示 10 秒一次的采样频率足以满足异动捕捉需求，无需追求毫秒级实时性。
4. **架构简化**：移除 `polymarket-websocket-client` 依赖，降低系统复杂度。

## 目标
- 移除所有 WebSocket 相关代码和依赖。
- 实现基于 `sampling-simplified-markets` 接口的全局轮询机制。
- 保持现有的滑动窗口异动检测逻辑。
- 支持 10 秒一次的采样频率。

## 风险与权衡
- **实时性下降**：从毫秒级延迟增加到秒级延迟（最大 10s + 网络延迟）。
- **API 频率限制**：需确保 10s 一次的请求不会触发 Polymarket 的 Rate Limit。
- **数据遗漏**：极短时间内的价格剧烈波动（如 1s 内拉升又回落）可能无法被捕获。
