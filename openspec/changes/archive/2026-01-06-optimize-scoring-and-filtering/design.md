# 设计文档：优化打分与过滤

## 架构推理

### 1. 关联性分析的实现挑战
全量分析多钱包关联性（Graph Analysis）需要索引器支持（如 Bitquery 或 Graph Protocol），仅靠 RPC 节点难以在实时路径上完成。
**决策**：
在 MVP 阶段，关联性分析（10%权重）将采用简化策略：**“同源资金检测”**。
- `ChainAnalyzer` 将尝试识别钱包的“注资地址”（Funding Address，即发起第一笔 ETH/MATIC 转账给该钱包的地址）。
- 如果在前 20 名持仓者中，发现 >= 2 个钱包拥有相同的非交易所注资地址，则判定存在关联。
- *注意*：需维护一个简易的“交易所/桥接白名单”以避免误判（如 Coinbase Hot Wallet），或若无法识别则暂不计入此项分数，保持实现简单。

### 2. Crypto 市场的精细化过滤
Polymarket 上 Crypto 类市场数量巨大且噪音多。我们需要区分“赌博型”（短时、涨跌）和“价值型”（Pre-market, 重大事件）。
**策略**：
- **正则表达式匹配**：使用 Regex 匹配 Title/Slug 中的关键词。
    - 排除：`/(Bitcoin|Ethereum|ETH|BTC) Price|Up or Down|High|Low/i` 结合时间关键词 `15m|1h|4h|Daily`。
    - 排除：Category 为 `Sports`。
    - 保留：包含 `Pre-market` 不受上述排除规则限制。
- **流动性检查**：在 Data API 返回的数据中直接读取 `liquidity` 字段，若 `< 10000` 直接丢弃，不进行后续处理。

### 3. 打分系统重构
`Scorer` 类将不再是一堆 `if-else` 的硬编码，而是改为基于权重的配置化计算。
每个维度计算出一个 0-1 的系数，乘以此维度的最大分值。

| 维度 | 权重 | 计算逻辑摘要 |
| :--- | :--- | :--- |
| 新鲜度 | 30 | Tx < 5 (1.0), Tx < 20 (0.75), Tx < 50 (0.4) |
| 专注度 | 30 | MarketCount == 1 (1.0), < 3 (0.5) |
| 本市场持仓 | 20 | >$50k (1.0), >$10k (0.75), >$1k (0.3) |
| 关联性 | 10 | 发现同源注资 (1.0), 否则 (0) |
| 总资金 | 10 | >$50k (1.0), >$10k (0.5) |

总分 = Σ(维度分值)
