## 需求
### 需求：市场订阅与过滤
系统必须订阅 Polymarket 的实时价格流，并仅处理特定类别的市场。

#### 场景：排除特定类别的市场
- **给定** 系统已启动并连接到 Polymarket WebSocket。
- **当** 收到一个属于 "Crypto" 或 "Sports" 类别的市场更新时。
- **那么** 系统应忽略该更新，不进行异动分析。

#### 场景：处理目标类别的市场
- **给定** 系统已启动。
- **当** 收到一个非 "Crypto" 且非 "Sports" 类别的市场更新时。
- **那么** 系统应将其传递给异动检测逻辑。

### 需求：价格异动检测
系统必须能够识别并报告价格的显著波动。

#### 场景：检测到价格波动超过 5%
- **给定** 市场 A 的上一个记录价格为 0.50。
- **当** 收到市场 A 的新价格为 0.53（波动 6%）或 0.47（波动 6%）时。
- **那么** 系统应输出异动警报，包含市场 ID、当前价格和波动幅度。

#### 场景：价格波动低于 5%
- **给定** 市场 A 的上一个记录价格为 0.50。
- **当** 收到市场 A 的新价格为 0.51（波动 2%）时。
- **那么** 系统应更新内存中的最新价格，但不触发警报。

### 需求：高阶市场过滤
系统必须在监控源头过滤掉低价值或高噪音的市场。

#### 场景：过滤低流动性市场
- **给定** 一个市场发生价格异动。
- **当** 该市场的流动性 (Liquidity) 小于 $10,000 时。
- **那么** 系统应忽略该异动，不进行打分或推送。

#### 场景：过滤短时 Crypto 期权
- **给定** 一个 Crypto 类别市场。
- **当** 其标题或描述包含 "15m", "1h", "4h", "Daily Up/Down" 等短期/二元期权关键词时。
- **那么** 系统应将其排除。

#### 场景：排除体育博彩
- **给定** 一个市场。
- **当** 其类别为 "Sports" 时。
- **那么** 系统应将其排除。

#### 场景：保留 Pre-market
- **给定** 一个名为 "Bitcoin September Pre-market" 的市场。
- **当** 系统进行过滤检查时。
- **那么** 即使它包含 "Bitcoin"，也应因包含 "Pre-market" 关键词而被**保留**。
